Hint: Try the new command-based protocol by starting pide_mcp or pide_ai with -p 0, which opens a TCP port for command-based interaction. The agent is informed about the location of the accompanying CLI in the MCP instructions (or simply tell it that the CLI is in the PIDE MCP/AI folder if you don't use MCP).

My impression so far is that agents are more effective using it. The drawback is that everything gets even more opaque: ad-hoc bash and python scripts, mixing sed, grep, PIDE AI calls, JSON parsing, etc. :see_no_evil:

Besides that, I published another useful update today and hope that's the final big change before the release:

Updates

  • get_session_state can now wait for termination or failure with timeout.
  • get_state can be alarmed about failed commands outside its range but inside the same theory
  • Theories without a final end are reported as failed.
  • For developers: I finally cleanly separated the in-memory <--> disk operations.
