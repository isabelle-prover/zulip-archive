Side-remark: there is no reason to believe that this will be the last

Indeed, we should use a the verified proof checker [1] since
implementation errors can inadvertently occur. I have made a practical
tool out of it here [2].

The main problem is that our proofterms are stored in compressed form
and uncompressing some of the big smt-generated proofs is too slow;
there is a good chance that the zproof implementation [3] would work
much better here.

Anyway, with the tool I have stumbled on the next problem: Quickcheck
generates equations for datatypes that it axiomatizes with skip_proof.

Those are immediately rejected by the proof checker. Turns out rightly
so, because one can prove False with these equations (see below)!

The cheat_tac invocation was introduced in (8fdfa9c4e7ed)
for performance reasons; perhaps this is no longer required and we can
revert back to produce a proper proof?

Note that the problem here abuses the fact that deps are not tracked
with the skip proof construction, but fundamentally these equations do
need a termination argument to be sound, so a 'fix' for the former
doesn't solve the underlying problem.

Fabian

text ‹Simple helper›

definition flip_result ::
  "(bool × Code_Evaluation.term list) option ⇒
    (bool × Code_Evaluation.term list) option"
  where "flip_result r = (if r = None then Some (True, []) else None)"

lemma flip_result_no_fixed_point: "r ≠ flip_result r"
  by (cases r) (simp_all add: flip_result_def)

text ‹
Datatype definition yields theorem to generate terms of the datatype,
with skipped proof.

The theorem states that full_exhaustive of 'a container is built from
full_exhaustive of 'a.

However, the generator is actually defined as \<^const>‹undefined› and
the proof of the theorem is
skipped, so this dependency is not recorded.
›
datatype 'a container = Container 'a
declare [[show_types]]
thm container.full_exhaustive_container.simps
ML ‹Thm_Deps.all_oracles @{thms container.full_exhaustive_container.simps}›

text ‹Hence, we can instantiate full_exhaustive for 'a, calling
full_exhaustive for 'a container:›

datatype (plugins del: quickcheck_full_exhaustive) elem = Elem

instantiation elem :: full_exhaustive
begin

definition
  "full_exhaustive_elem
    (_ :: elem × (unit ⇒ Code_Evaluation.term) ⇒ (bool ×
Code_Evaluation.term list) option)
    i =
      flip_result
        (Quickcheck_Exhaustive.full_exhaustive
          (λ(_ :: elem container × (unit ⇒ Code_Evaluation.term)). None)
        (i + 1))"

instance ..

end

text ‹This is a cycle and gives a contradiction due to flip_result:›

lemma generated_cycle:
  "Quickcheck_Exhaustive.full_exhaustive
    (λ(_ :: elem container × (unit ⇒ Code_Evaluation.term)). None) 1 =
   flip_result (Quickcheck_Exhaustive.full_exhaustive
    (λ(_ :: elem container × (unit ⇒ Code_Evaluation.term)). None) 1)"
  by (subst container.full_exhaustive_container.simps)
     (simp add: full_exhaustive_elem_def)

theorem missing_check_False: False
  using generated_cycle flip_result_no_fixed_point by blast
