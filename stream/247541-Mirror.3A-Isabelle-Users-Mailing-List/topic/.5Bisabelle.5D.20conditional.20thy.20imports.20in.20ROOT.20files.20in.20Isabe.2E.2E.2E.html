Subject: [isabelle] conditional thy imports in ROOT files in Isabelle2026-RC3

The new handling of theory options in ROOT files (empty theory instead of not loading the theory) is preventing us from applying this kind of pattern:

theories [condition = "SKIP_DUPLICATED_PROOFS", quick_and_dirty, skip_proofs]
"Include_C"
theories
"Include_C"

We’re doing that to speed up development builds significantly when the dependencies of theory Include_C are already checked in other sessions. Of course we do want them to be properly checked for “real” proof check runs when we are not developing and SKIP_DUPLICATED_PROOFS is off.

Have others run into this? What are our options?

Cheers,
Gerwin

We use skip_proofs in the following ways in l4v:

  1. a switch in jEdit that allows the user interactively switch skip_proofs on and off

This is for when you are certain the proofs will work, but you have for instance changed a definition that is far away. I think Toplevel.skipped as proposed is likely to work for this, the jEdit toggle just needs to be adapted.

The 2025-2 version of this is here:
https://github.com/seL4/isabelle/commit/a9f7c5724f03586c021b344ac34c415ffd70ffaa

  1. a defer_proofs mode (+ switch in jEdit), that initially skips proofs, but schedules all of them as future

This is for when you are less certain the proofs will work and they need to be re-checked, but you still need to get back quickly. It is almost as fast as pure skip_proofs to return to the previous editing position, but will check proofs eventually. Error behaviour is different to normal proof check mode, because it initially assumes all lemma statements are true. The implementation of this is hacky, which is why we never contributed it back, but we use it almost daily.

This currently uses the Skipped_Proof node and init_skipped_proof in Toplevel, and Proof.global_skip_proof. It introduces its own Goal.defer_proofs_enabled which is modelled on Goal.skip_proofs_enabled. I think this can also be ported to the top-level-only proposal, but I am less sure without actually attempting it.

Not sure if you really want to look at it (like I said, it’s hacky), but the 2025-2 version of this is here:
https://github.com/seL4/isabelle/commit/ac38b545457822ae2d9f4144eb9c97dd34e4453a

  1. some proof tools explicitly check skip_proofs_enabled(), for instance like this:

fun maybe_cheat_tac ctxt thm =
if (Goal.skip_proofs_enabled ())
then ALLGOALS (Skip_Proof.cheat_tac ctxt) thm
else all_tac thm;

The quick_and_dirty was intended for packages like datatype, BNF, etc, which are checking quick_and_dirty explicitly to reduce work. The difference is marginal, though, not worth spending time on. It was a leftover from times when machines were a lot slower.
OK, this is what I suspected.

For completeness, I should say that we do have a separate use of quick_and_dirty in the C parser, which declares many small records and some very large records. Having quick_and_dirty on for that invocation makes a larger difference (about 4-5 min wall time and 20 min CPU time), but we are planning to use a different mechanism for this (switching on/off the option just around the relevant command, instead of in the ROOT file).
