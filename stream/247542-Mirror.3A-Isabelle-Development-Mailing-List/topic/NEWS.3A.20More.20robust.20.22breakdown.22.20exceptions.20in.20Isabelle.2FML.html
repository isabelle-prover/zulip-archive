Topic: NEWS: More robust "breakdown" exceptions in Isabelle/ML

Email Gateway (Nov 12 2026 at 21:27):

From: Makarius <makarius@sketis.net>

* ML *

  • Exceptions General.Overflow and General.Size need to be used in
    qualified form: to make it harder to use them casually. Minor
    INCOMPATIBILITY.

  • Predicate Exn.is_interrupt_breakdown now covers General.Size and
    General.Overflow as well, in addition to Exn.Interrupt_Breakdown before.
    In particular, these exceptions are no longer handled by the "can" or
    "try" combinators, or \<^try>‹... catch ...› expressions.
    INCOMPATIBILITY: subtle change of semantics of program exceptions; need
    to use Exn.capture if the Isabelle/ML evaluation should be checked under
    program control.

This refers to Isabelle/867cbd97b013. It is another attempt to keep accidental
system breakdown out of the normal semantics of the ML program.

General.Size typically happens on blobs that are too large, notably for type
string and array (the latter is hardly ever used). In very rare situations,
exception General.Size shows up for different purposes in some odd libraries
--- we can probably afford that.

General.Overflow should show up extremely rarely, because our type int is
already unbounded and should never overflow.

Such very rare events are better not handled implicitly, as in our "try" family.
