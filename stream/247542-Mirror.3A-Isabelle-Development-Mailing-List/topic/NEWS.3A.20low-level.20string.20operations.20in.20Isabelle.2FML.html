* ML *

  • Various low-level string operations have been renamed as follows.
    INCOMPATIBILITY.

    nth_string ~> String.nth_str
    fold_string ~> String.fold_str
    fold_rev_string ~> String.fold_rev_str
    exists_string ~> String.exists_str
    forall_string ~> String.forall_str
    member_string ~> String.member_str
    raw_explode ~> String.explode_str
    translate_string ~> String.translate_str
    Bytes.exists_string ~> Bytes.exists_str
    Bytes.forall_string ~> Bytes.forall_str

This refers to Isabelle/ad6679bf69a4.

Further note that String.explode_str avoids the stack-based implementation of
structure SML90, which could cause problems with very large input. This was
discovered by Martin Desharnais-Schäfer.

As a reminder, see also the "implementation" manual (a4b37e45d75b):

paragraph ‹Historical note.›
text ‹
In the original SML90 standard the primitive ML type \<^ML_type>‹char› did not
exist, and \<^ML_text>‹explode: string -> string list› produced a list of
singleton strings like \<^ML>‹String.explode_str: string -> string list› in
Isabelle/ML today. When SML97 came out, Isabelle did not adopt its somewhat
anachronistic 8-bit or 16-bit characters, but the idea of exploding a string
into a list of small strings was extended to ``symbols'' as explained above.
Thus Isabelle sources can refer to an infinite store of user-defined
symbols, without having to worry about the multitude of Unicode encodings
that have emerged over the years.
›
